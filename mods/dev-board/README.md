# dev-board

A Claude Code mod for a boss session in the Claude desktop app: a live board of the sessions it started (its workers), from `dev desktop board --json`.

- `/board` opens the **Workers** pane (the desktop app docks it in the right side panel), titled with its counts while open (`Workers · 3 · 1 needs you`), its tiles in sections by status, each with its count beside it, empty ones hidden: **Needs you** (red), **Working** (working, stuck, rate-limited; accent), **Waiting** (waiting, blocked, review ready; amber), **Idle** (idle, stopped; muted). A section's color marks its header; color on a tile means it asks to be looked at: Needs you and Waiting tiles' left rule takes their section's, Working and Idle tiles' a dim grey, and only a Needs you status is red (the current task step keeps its section's color). Colors are the app theme's, so light and dark both work.
- The first `/board` in a desktop session also asks it to act as boss: `dev-board: /board opened — load the dev-board:boss skill and act as boss for this session's workers.`, which starts a turn once it is idle (a prompt, not a command's hidden context, so the skill loads now rather than at the next message). It asks once per session: the mod keeps that in the session's state, so opening the pane again or a reload of the mod asks nothing; a prompt the app refuses shows as a toast and isn't retried.
- The mod bundles the boss rules as its `dev-board:boss` skill (`skills/boss/SKILL.md`): a copy of `internal/skill/desktop-boss/SKILL.md` named `boss`, which `go test ./internal/skill` checks and `go test ./internal/skill -update` rewrites. Edit the source, not the copy.
- A tile, its rows all starting under its name, the fold button and dot beside them, in blocks a small gap apart (name and title; its question; what it does; tasks; buttons):
  - beside the rows: ▾/▸ (fold) and dot (●) colored by its section, not the app's state: red under Needs you, amber under Waiting, green under Working, grey under Idle, dimmer once stopped (so a worker whose open dialog waits on the person is red, though the app has it busy);
  - header row, never wrapping: the worker's name (its title when it has none; cut to fit) and, at the right, its time in its state (busy or idle; since its last activity once stopped: `12m`, `now` under a minute); under it, in a smaller face, its title where it differs from the name;
  - status row, in a smaller face (folded, the row's size), its status red and semibold under Needs you, else subtle, cut to fit, its markdown backticks and bold stripped: status and what it says (`blocked · pick one`, `rate-limited · resumes 18:05`, `stuck · no progress for 17m`), the status left out where it repeats the section (`allow Bash: …` or `waiting for you` under Needs you, what its tool call says it does under Working (`Wait 20s, then count hook files`, a Bash or Agent call's `description`; else the tool, `Bash`; between its tools the first line of what it last said this turn, else its last finished call's `description`, else `working`, so the row stays; then its background commands and agents still running, `· 1 background running`), `Auto-fix: PR #80` under Waiting); then, never cut, the model (`opus`, `sonnet`, `haiku`, `fable`, else the app's id) and its effort, and the context use: `working · opus·medium · 9%` (no effort, the model alone; no model, the context use alone; neither, the row is the status alone; with a question showing, the model and context alone);
  - branch row, only with a branch: the branch in a mono face, cut at its start so its unique end shows;
  - a row per PR, cut to one line: its state icon (open green, merged purple, closed red, each its own shape), `PR #93` (click to open) and its state, then for an open PR its CI icon from `gh pr checks` (✓ passed or skipped, ✗ any failed or cancelled, else a clock while any runs; none until read or with no checks) and the names of the checks that make it (the failed ones, the running ones, else all). The icons are SVG drawn for this mod, their `alt` read aloud (`PR #93 open`, `CI failed`); the terminal draws glyphs (○ ◆ ✕, ✓ ✗ …) in the theme's colors;
  - the app's verdict on its last turn in words (`review ready`, not `review_ready`; only a detail the status row lacks, when the status says the verdict or is waiting: the worker's own marker is newer) and what it needs (`needs: …`; not beside a question's options, which ask it), health notes, the last two lines of its newest reply, one beside a verdict (dim; code fences, turn-end markers such as `IDLE`, a line repeating the status row, its question or the need its options answer, and one naming every option among list words only (`Pick a reply: Per package, or Total only.`; not `Per package is slower; Total only skips files.`) skipped) without list markers, backticks or bold, a link as its text, each line cut to one row; the task list; buttons.
  - task list, from the worker's update_plan: `Tasks` (lined up with the steps' marks, in their size), a progress bar (done steps green on a faint track, on the terminal a thin dim one, so an empty bar reads as empty) and the count with **▸**/**▾** (a button, its count and arrow its only label, that unfolds or folds it: `2/5 ▸`; no other label, as the desktop draws a label in place of them); collapsed, one row: the step at hand after them, cut to fit; expanded, every step under it, a mark and its text cut to one row: ● done (green, dimmed), ◐ current (in the section's color, its text stronger), ○ pending. With more than 7 steps, the leading done steps but the last fold into `● n done`, and the steps past the room into `○ n more` (the current step always shows).

  Idle tiles are folded to one row, in the same card, so unfolding only opens the body under the arrow, dot and name (name, its PRs' state and CI icons, task progress, status where it doesn't repeat the section, time; name and status cut to fit), unless they have a health note or a `needs: …`; the rest are open. **▸**/**▾** (the arrow its only label) folds or unfolds one; that choice sticks across polls and status changes for the session, until the worker asks a new question, which opens it. A folded tile with a note or a need ends in ⚠.
- Buttons per tile:
  - **Open** opens the worker's session in the app (`claude://code/continue?session=<id>`); the main button for Needs you and Waiting tiles; on Working and Idle tiles, and on a tile showing a question's options, it and **Message…** are dim text buttons.
  - **Message…** opens a field (labelled `Message <name>`) with **Send** and **Cancel**; Enter or Send asks the boss to relay its text: `dev-board: message <name> (<id>): <text>`; a message the app refuses opens the field again, holding its text.
  - **Archive**, shown once `dev delivered <worktree>` exits 0 for a worker with a PR and a worktree that is neither busy nor waiting on something that will wake it (a `WAITING (…)` marker; such a worker shows no Archive), else the tile says `not delivered: <why>`; checks it again and asks the boss to archive it: `dev-board: archive <name> (<id>): dev delivered exited 0`. A worker going busy drops its last check.

  The prompts wait for the boss to go idle; a toast says each was queued, or why not. A worker's permission prompt can't be answered here: answer it in its session (**Open**).
- A worker's question (AskUserQuestion) shows on its tile in place of the status row: each question's header and text, its options buttons in one row that wraps when narrow (one question with one pick: the first leads; else the picked ones), the described ones as `label: description` in a smaller face under it. One question with one pick: pressing an option answers it. A multi-select (☐/☑) or several questions (○/◉ each): pick, then **Send**, which says which question still lacks a pick. The answer is the person's pick, as the dialog would send it (a multi-select's labels comma-joined), and the engine aborts the worker's own dialog; a pick there first wins instead, and the board's answer is refused. The tile then says `sent: …; waiting for the worker` until the question is gone.

  How: every desktop session loads this mod, so a worker's own copy sees its AskUserQuestion. While the dialog is open it writes the question to `questions/<app session id>.json` in dev's state directory (`~/.local/state/dev/desktop/`); the board runs `dev desktop answer <id> <tool use id>`, which writes `<id>.answer.json` (atomically, only for the question still open), and the worker's copy answers with it. Both files go once it is answered, either way. `dev desktop board` removes those its mod left behind (a reload, a crash): of a worker no longer running (once the file is a minute old: one started since the board read the live files may have just written it), or running no turn, or whose transcript has the answer; and anyone's older than a week. A question read only from the transcript (a worker whose mod is older, or could not write the file) can't be answered here: its options open its session, and the tile says so. A permission prompt still can't be answered here: **Open**.
- A worker whose last turn ended on a wrap_up question (`ask`) shows it the same way, its reply buttons the options (of the first two actions, the ones the app draws; app actions such as Commit left out), and its tile is open even when idle. A blocked one (`blocked: true`) puts the worker under Needs you, the question its status, whatever its last lines say (an `IDLE` marker says only that nothing runs). Pressing one answers it as the person would in the worker's session: the board writes the label to `questions/<id>.reply.json` and the worker's own copy of the mod submits it as its next prompt, the person's own words. That route is taken while the worker's copy listens for that ask (it rewrites `questions/<id>.listen` every 2 s, naming the wrap_up its last turn ended on; `dev desktop board` marks the ask `listening` while that file is under 10 s old, names it, and the worker runs); else the press asks the boss to message the worker that label (`dev-board: message …`, as **Message…** does). The worker takes a reply once, and only for the wrap_up its last turn ended on: one for an earlier ask, one written over a minute ago, or one arriving once a turn started is dropped. A reply the worker still waits for 10 s on (not taken, or its prompt refused) brings the buttons back, with a toast. Without reply buttons it is answered with **Message…**. It goes once the worker gets a message or starts a turn; a busy worker's open AskUserQuestion is newer and shows instead.
- Health notes (stuck, a decision unanswered, high context, rate-limited, resume due) show on their tile. A note the boss hasn't had yet goes to it as one prompt per poll for all new ones, e.g. `dev-board: fix-login stuck: no progress for 17m; docs-api resume due: rate limit reset 18:05: resume it`, which starts a boss turn once it is idle. The keys sent are kept in the session's state, so a reload of the mod sends none again; a prompt the app refuses shows as a toast and isn't retried.
- The band above the prompt sums them up, e.g. `1 needs you · 3 workers · 1 busy · 1 blocked · PR #78 open` (a worker that needs you counted there only, not busy or blocked too), dim, its `needs you` part red; hidden when there are none (or while a survey shows).

Every 2 s it runs `dev desktop board --json --boss $CLAUDE_CODE_HOST_SESSION_ID`; `gh pr checks` per open PR and `dev delivered` per worker not busy with a PR run at most once a minute each. Without `gh` on the app's `PATH` the PR's row says why. A failure (no `dev`, an old `dev` without the command, no app record for the session) shows its error in the pane, with a ⚠ and that it retries every 2 s; with no error and no workers it says `No workers yet`; files `dev` could not read show as warnings above the tiles, a ⚠ footnote row each, as does a live session status it doesn't know (that worker shows busy). A desktop session loads the mod once, when its Claude starts (unless `CLAUDE_CODE_PLUGIN_DIR_WATCH=1`, which reloads it): once the files it loads (`.claude-plugin/plugin.json`, `hooks/`, `skills/`) are newer, the board warns (`dev-board mod changed 19:17, after this session started 17:27: start a new session to load it`): it runs the older copy; start a new session (or restart the app) to load them. Outside a desktop app session (no `CLAUDE_CODE_HOST_SESSION_ID`) it runs no `dev`; the pane says why.

## Load it

1. A `dev` build with `dev desktop board` on the app's `PATH`. The desktop app's `PATH` may lack `~/go/bin`: if the pane says `dev` can't start, set `DEV_BIN` at the top of `hooks/register.tsx` to its absolute path.
2. Name this folder in `CLAUDE_CODE_PLUGIN_DIRS` in the `env` block of `~/.claude/settings.json` (absolute paths, `:`-separated; never a project's settings):

   ```json
   { "env": { "CLAUDE_CODE_PLUGIN_DIRS": "/path/to/dev/mods/dev-board" } }
   ```

3. Start a new desktop session (or restart the app) and run `/board` in the boss session.

## Develop

```bash
claude plugin validate mods/dev-board
claude plugin test mods/dev-board
```

The engine writes the API types into `.claude-plugin/types/` (ignored by git) once it loaded the mod; `tsc -p mods/dev-board` type-checks it then.
